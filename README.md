## Step 1 — Train & compare models (Part A + B)

```bash
# Open and run the notebook (Jupyter / VS Code / Colab)
jupyter notebook Task3_Model_Comparison.ipynb
```

What the notebook does:
1. Reuses the Task 2 cleaning + feature-engineering pipeline
2. Trains **Linear Regression**, **Ridge**, **Decision Tree**, **Random Forest**, **Gradient Boosting**
3. Reports **MAE, RMSE, R²** on the held-out test set
4. Selects **Random Forest** (best test metrics)
5. Saves:
   - `uber_fare_model.pkl` — full sklearn Pipeline (preprocessor + model)
   - `feature_columns.pkl` — ordered list of feature names
   - `segment_bins.pkl` — distance quantiles for trip_segment

## Step 2 — Run the Flask app (Part C)

Make sure the three `.pkl` files are in the same folder as `app.py`, then:

```bash
python app.py
```

Open your browser at: **http://127.0.0.1:5000**

### Form fields

| Field | Required | Description |
|-------|----------|-------------|
| Trip distance (km) | Yes | Numeric, > 0 |
| Pickup date & time | Yes | datetime-local picker |
| Pickup lat / lon | No | Improves airport-proximity features |
| Dropoff lat / lon | No | Used for bearing calculation |

### Pipeline applied to every request

1. Validate inputs (type, range, required fields)
2. Extract hour / day / month / weekday / year from datetime
3. Engineer flags: `is_night`, `is_weekend`, `trip_segment`, `near_jfk/ewr/lga`
4. Compute airport distances & bearing (if coordinates given)
5. Build a single-row DataFrame matching training columns
6. Run the saved Pipeline → scaled features → Random Forest prediction
7. Display the predicted fare

## Step 3 — Testing (Part D)

Test at least **3 successful predictions** through the UI, for example:

1. **Short daytime trip**  
   Distance: `2.5` km · Date: weekday morning · Coordinates: Midtown → nearby

2. **Airport trip**  
   Distance: `18` km · Date: any · Coordinates near JFK

3. **Late-night weekend trip**  
   Distance: `6` km · Date: Saturday 23:30

Also test **1 invalid case**:
- Leave distance empty, or enter distance = `-5`, or omit the datetime  
- The app should show a clear error message and **not** crash

Take screenshots of the filled form + result page for each test and include them in your submission.

## Model choice (summary)

**Random Forest** was selected because it achieved the best test-set MAE, RMSE, and R² while remaining fast enough for real-time inference. Linear / Ridge models underfit the non-linear fare–distance–time relationship; a single Decision Tree overfits more easily.
